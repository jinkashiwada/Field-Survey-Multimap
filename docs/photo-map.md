# 浸水域判読支援ツール

既存マルチマップと別の入口 `/photo-map/` を持つ、端末内で動作する静的Webアプリです。開発時は `npm run dev` 後に `/photo-map/` を開きます。GitHub Pagesではリポジトリのサブパスに続く `/photo-map/` になります。

## 基本操作

1. JPEG・PNG・WebPを追加し、左の一覧で編集する写真を選びます。「地図と位置合わせ（対応点）」を押し、写真と地図に同じ番号の対応点を4組以上置いて「計算・適用」を押します。対象を囲むように6〜10点程度配置し、地表と高さが異なる屋根などは避けてください。
2. 写真・地図を拡大して確認し、必要なら点をドラッグまたは数値入力で修正します。「検証点」は計算に使わず、独立した残差確認に使います。修正後は再び計算・適用してください。
3. 「写真＋地図2面」で比較できます。左右の境界をドラッグ、またはフォーカスして左右矢印でサイズを変更できます。各画面の右上で最大化できます。「地図1面」またはEscape（作図・ポップアップの操作中はそれを先に終了）で写真選択を解除し、地図Aを広く表示します。写真を再選択すると比較表示に戻ります。地図には現在のズームと緯度に応じた縮尺線を常時表示します。
4. 写真一覧の各行に、地図A・Bへの表示チェックと透過度スライダーがあります。一覧の上では、地図A・Bの写真をそれぞれ一括で表示・非表示にでき、全写真の透過度も一度に調整できます。緑は位置合わせ済み、黄は未反映の変更あり、灰色は未登録です。⠿ をドラッグして重なり順を変更できます。編集対象の写真は地図上で一時的に最前面となり、輪郭が強調されます。
5. 左の「選択写真の編集」から「矩形で切り抜く」を選び、写真で対角の2点をクリックします。「不要部分を隠す」はテロップ等を囲み、ダブルクリックで完了します。元画像・対応点座標を変更せず、投影から除外します。写真名・日時・出典・メモは「写真の情報・名称」を開いて編集します。
6. 重ねる情報は各画面の「レイヤー」から、その場で開くポップアップで設定します。写真側の背景・河川・道路・ハザードは逆投影されます。写真画面の見出しには逆投影、地図A・Bの見出しには各面の重畳レイヤーすべてに同じ透過度を適用するスライダーがあります。背景地図はこのスライダーの対象外です。持込みGISの追加・管理もレイヤー設定内にあります。
7. 作図したい写真・地図の「作図」から「線を描く」「面を描く」を選びます。その画面で頂点をクリックし、ダブルクリックで完了すると、同じ場所に作図の属性編集が開きます。「頂点を編集」はドラッグで移動・追加、Alt＋クリックで削除です。画面内の「終了」またはEscapeで移動操作に戻ります。ほかの画面は作図モードに切り替わりません。作図一覧・表示の絞込み・GeoJSON／KML書出しもこのポップアップにまとめています。
8. 写真画面の左右矢印でも写真を切り替えられます。地図上の投影写真にマウスを重ねると元写真名を表示し、クリックでその写真へ切り替えます。右クリックの「この写真以外を非表示」はその地図だけの一時表示で、「単独表示を解除」で元の表示設定に戻ります。「最前面／最背面に移動」は写真一覧の順序を変更し、ZIPに保存されます。
9. ZIPで保存します。受取人は同じツールの「ZIPを開く」から編集を継続できます。途中の作業は、変換画像の同梱を外しても保存できます。画像だけを共有する場合は「オルソ画像エクスポート」を使います。

## 比較画像の書き出し

「オルソ画像エクスポート」の専用画面で下絵・重畳情報・位置合わせ済み写真と濃さを選びます。重畳情報の濃さはプレビューへ即時反映されます。写真は上ほど前面になり、一覧のドラッグ・矢印に加え、地図上の投影写真を右クリックして前面・背面・最前面・最背面への移動や非表示ができます。地図をドラッグ・ズームし、右ドラッグで回転できます。黄色い矩形の角・辺・内部を動かして出力範囲を指定します。矩形内の縮尺・方位・出典・右下のクレジットは矩形と一緒に動き、その見た目と同じ配置でPNGに入ります。作業画面の表示設定は変更されません。

ZIPには、選択した下絵とオルソ写真を合成した主画像、および同じ地図画角の通常地図、航空写真、航空写真＋河川線形、洪水浸水想定区域図（L2・L1）、色別標高図、解析用色別標高図を初期設定で収めます。浸水継続時間も選べます。比較地図にはオルソ写真を重ねません。浸水域の作図は主画像の重畳情報の上で切り替え、初期オフです。表示中の位置合わせ済み写真ごとに、全国最新写真をその斜め写真面へ逆投影した `_reference` と、切抜き・マスクを適用した元写真の `_after` を並べて収めます。全国最新写真が災害前の画像とは限らないため、`_before` とは表記しません。

色別標高図には[国土地理院の公式凡例](https://cyberjapandata.gsi.go.jp/legend/Relief_hanrei.png)を画像内へ同梱表示し、海域部の出典も明示します。解析用色別標高図は出力矩形内16地点のDEM10B標高を標本抽出して配色レンジを決め、その上下限と中間値を画像内の凡例に表示します。標高が取得できない場合は設定済みレンジを使い、その旨を凡例・画面・`sources.txt` に記録します。

地図画像には縮尺・方位・加工表示・出典を入れます。ツールのクレジットを表示する場合は「浸水域判読支援ツール」（東京理科大学 水理研究室）を使用、公開URLの2行を入れます。クレジットは任意で、書き出し画面のチェックを外すと地図・斜め写真の両方から除外できます。地図データの出典・加工表示はチェックに関係なく残します。詳細な出典と取得時の注意は `sources.txt`、利用と権利の案内は `USAGE_AND_CREDITS.txt` に記録します。画像ZIPには編集用の `project.json` や元画像ファイルを含めません。地図画像は回転・重畳済みの閲覧用PNGであり、GIS用の位置参照画像が必要な場合は作業ZIP内の `rectified/` を使用してください。

公開レイヤーの一部タイルが未収録または取得できない場合も、取得できた部分は出力に残します。未取得タイルがあれば、画面にはまとめて通知し、レイヤー別の件数を `sources.txt` に記録します。

対応点タブでは、対象写真以外の投影写真を一時的に隠します。適用済みの位置合わせがある写真は地図A下部のスライダーで透過度を調整できます。写真タブへ戻すと、ほかの写真の表示は元の設定に戻ります。位置合わせ前の写真には、地図情報を逆投影できません。

写真上で作図した図形は画素座標を保持し、位置合わせを修正すると地図上で移動します。地図上で作図した図形は地理座標を保持します。写真に紐付く図形を「地図位置を固定する」で地理座標へ変更できます。異なる写真の時刻の図形は自動で結合しません。

## データと機密性

- 写真・ファイル名・対応点・図形・プロジェクト名を開発者や外部サービスへ送信しません。画像処理、ZIP処理はブラウザー内です。
- アプリ本体の取得と公式地図取得には通信します。地図提供元には要求タイルの範囲、接続元IP等が伝わり得ます。
- 自動永続保存やクラウド同期はありません。再読込み・タブ終了前にZIPを保存してください。未保存時はブラウザーの終了確認を要求しますが、ブラウザー終了・異常終了からの復旧を保証するものではありません。
- 元画像をそのまま保存するため、EXIFなど元画像のメタデータもZIPに残ります。
- ZIPから外部の任意URL・KML NetworkLink・スクリプトを読み込むことはありません。地図レイヤーは組み込みの公式一覧だけを使います。

## 形式とGISへの受渡し

ZIPの `project.json` が編集情報の正本です。`originals/<写真ID>` は元ファイルで、元の名称・MIME型は `project.json` にあります。`transforms.json` でも確定行列と採用したGCPを確認できます。

作業ZIPと画像ZIPに `USAGE_AND_CREDITS.txt` を含めます。公開ページの利用・共有は自由で、ツール自体のクレジットは任意です。地図など第三者データの出典・加工表示と、元写真・持込みGISの権利は別途確認してください。作業ZIPには元画像のEXIF等も残ります。

公開スキーマは [project.schema.json](../src/photo-map/project.schema.json) のv2です。同じスキーマをZIPの `schema.json` に同梱します。v1の作業ZIPは重畳レイヤー一括透過度を100%として読み込み、v2へ移行します。スキーマ検証に加え、読込み時に参照関係、行列と逆行列、座標、画像寸法などの整合性も確認します。

- 写真座標：EXIFの向きを適用した元解像度画像、左上画素中心 `(0, 0)`、右向きX・下向きY。
- GCPの地図座標：EPSG:4326、経度・緯度の順。
- ホモグラフィー：行優先の9数値、同次列ベクトルを使用。`H × [画像X, 画像Y, 1]` を第3成分で割るとEPSG:3857座標。
- 地図に固定した図形：EPSG:4326。写真に追従する図形：写真IDと画素座標。
- `drawings.geojson`：地理座標に変換可能な全図形。表示のオン・オフにかかわらず出力。未登録写真の図形はZIPの編集情報には残り、GIS出力からは除外。
- `rectified/<写真ID>.png/.pgw/.prj`：EPSG:3857の北上・等間隔格子。透過PNGは背景地図を含まない画像単体。PGWは左上画素の中心を記録。GDAL・QGIS向けにCRSの自動認識用の `.png.aux.xml` も同梱します。これらは同じフォルダーに展開し、CRSが自動認識されないGISではEPSG:3857を指定。
- 変換画像の初期長辺は4096 px、64〜8192 pxを指定可能。最大3200万画素。明示範囲を指定しない場合は写真の切抜き範囲を覆う矩形。
- 画面PNGはその時点の参照用です。公開地図タイルは同梱せず、再読込み時の地図は提供元の更新を反映する場合があります。

## 実装

新ツールの状態は既存のAppContext・URL・ピン保存から独立しています。共通の公式レイヤー定義・Sourceキャッシュ・スタイル・GIS codecを利用します。地図A・Bだけが同一Viewを共有し、写真のViewは画素座標です。

正規化DLTをSVDで解きます。4点の場合は8×9行列に零行を加え、右零空間の欠落を防ぎます。地上残差はEPSG:3857の数値差をそのまま距離とせず、経緯度へ戻して地上距離を算出します。計算用GCPと適用済みGCPのスナップショットを分離しています。

ZIP保存・読込み時の行列と逆行列の整合性は、適用済みの計算用GCPを中心とする正規化座標で、両方向の積を検証します。大きなEPSG:3857座標のまま積と単位行列を比較すると、桁落ちを不一致と誤判定するためです。未反映のGCP編集を検証の基準に使わず、保存済み行列の再計算・置換も行いません。2026-09-25にこの誤判定を修正し、合成した斜め写真の旧形式行列のZIP往復と、実際に異なる逆行列の拒否を回帰テストへ追加しました。

地図への写真投影はWebGLの逆写像です。画面画素→写真画素の行列をCPUの倍精度で合成してからシェーダーへ渡し、大きなMercator座標を直接GPUに入力しません。WebGL非対応ではWorkerで生成したラスタを表示します。地図の逆投影は写真の対象範囲だけを参照用Mapへ描画し、Workerで写真座標へ変換します。参照用Mapに投影写真を追加しないため、循環しません。

元画像はBlobで管理し、描画用の復号キャッシュ、GPUテクスチャ、代替表示のラスタキャッシュはそれぞれ128 MBを上限とします。画像の復号と各地図の代替投影は順番に実行します。地図用画像は長辺1024 px、写真用の概要画像は2048 px、拡大時のみ元画像の詳細を読み込みます。ZIPの生成・展開とラスタ書き出しはWorker内で行います。

## 制限と確認

- 対象：デスクトップ版Chrome・Edge。フルHD、125%相当の1536×864 CSS pxを基準に検証します。
- 画像1枚100 MB・6400万画素、元画像合計1 GB、最大100枚（通常利用は30枚程度）。ZIPのファイル数2000、展開合計2 GBまで。
- 平面近似のため、地形の起伏、建物高、レンズ歪み、GCPの誤判読は位置のずれとして残ります。4点時の小さい残差は精度の証明ではありません。地平線をまたぐ投影は範囲を切り直してください。
- 試験公開ベクトルの河川破線は概略位置のガイドであり、精密なGCPの基準には適しません。
- GeoTIFF、Shapefile、3次元復元、自動抽出、完全オフライン運用は対象外です。

`npm run check` でlint・型検査・単体テスト・本番ビルド、`npm run test:e2e -- e2e/photo-map.spec.ts` でブラウザーテストを実行します。E2Eは外部地図を固定タイルに置き換えます。合成画像で検証し、機密画像をCIやリポジトリに置きません。

2026-09-25の確認：既存画面を含む34件のE2E、64件の単体テストを実行済みです。画像専用ZIPでは、同一画角の地図8種、斜め写真ペアの寸法・切抜き一致、矩形と縮尺・方位の一体移動、右ドラッグ回転、写真の前後順、重畳情報の濃さのプレビュー反映、右クリック操作を固定地図データで検証しました。欠損した洪水タイルが混在しても取得済み部分を残すこと、標高図2種に凡例を配置することも確認しています。GitHub Pagesと同じサブパスの本番ビルドでも新画面のE2Eを確認しています。6000×4000画素の合成画像30枚の復元・編集・4096px変換画像を含む作業ZIP保存も検証しています。これは圧縮しやすい合成画像による確認であり、16 GB・内蔵GPUのWindows機や実写真での画像専用ZIPの所要時間・最大メモリー使用量の実測ではありません。GIS出力はGDALを含むRasterioとPROJで座標系・北上格子・画素値・既知地点を確認しました。

仕様の根拠：[ホモグラフィーの平面仮定（OpenCV）](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)、[World Fileの画素中心規約（GDAL）](https://gdal.org/en/stable/drivers/raster/wld.html)、[ハザードマップの出典・加工表示](https://disaportaldata.gsi.go.jp/hazardmap/copyright/copyright.html)。
