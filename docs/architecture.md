# アーキテクチャ

## 全体

React 19、TypeScript、Vite、OpenLayers本体、CSS Gridで構成する1ページの静的Webアプリケーションである。React RouterやOpenLayers用Reactラッパーは使わない。`AppContext` と `useReducer` が表示レイアウト・レイヤー状態・通知を管理し、ViewやVectorSourceのようなOpenLayersオブジェクトはContext内で一度だけ生成する。

## OpenLayers

- ペインごとに別の `Map`、TileLayer、VectorLayerを作る。
- 全Mapが同じ `View` を参照して中心、解像度、ズーム、回転を完全同期する。
- XYZ SourceはレイヤーID単位のキャッシュで共有し、4画面時の同一タイル要求を再利用する。
- 道路・鉄道・河川・等高線は、公式試験公開MVTのVectorTileSourceを共有し、Mapごと・用途ごとに別のVectorTileLayerとスタイルを持つ。
- ピン、現在地、読込みGISは用途別の共有VectorSourceを持ち、Mapごとに別のVectorLayerから描画する。
- ペインのResizeObserverで `updateSize()` を呼び、unmount時はobserver・イベントを解除して `setTarget(undefined)` とする。
- Raster、GIS、ピン、現在地はz-index順の別レイヤーとし、一つのタイル障害が他を止めない。

## 状態とデータフロー

表示状態はReducerからUIとペインへ一方向に渡す。View移動はOpenLayers内部で同期し、moveend後だけReactの中心ステータスを更新する。hash更新は250ms、DEMは300msデバウンスし、`history.replaceState` で履歴を増やさない。

ピンは `flood-multimap:pins:v1` へJSON保存する。破損・旧形式は空配列へフォールバックする。KML・GeoJSONはメモリー上だけに保持し、ページ再読込み時には消える。通常の表示URLにはピン・現在地マーカー・GIS地物を含めない。選択ピンの明示共有は以下の拡張で扱う。

## 選択ピンの共有設計

- 共有対象は1件。既存の地図hash v1へ`pin`パラメーターを追加し、バージョン1のJSONをURLSearchParamsで符号化する。コピー時は完成したhashをブラウザー標準`CompressionStream`でgzip圧縮し、base64url化した`#s=1.<token>`を生成する。公開サーバー、第三者短縮サービス、圧縮ライブラリは追加しない。通常の表示共有にも同じ圧縮を使う。
- 起動前に`#s=1`を`DecompressionStream`で展開し、`history.replaceState`で既存の`#v=1`形式へ戻してからReactを描画する。既存codecを二重化せず、従来URLとの後方互換性を保つ。圧縮非対応環境では送信時に従来形式へフォールバックする。不正token、32,000文字超のtoken、展開後72,000 byte超は拒否し、地図は既定状態で起動する。
- 送信時は現在のViewと表示設定を直接取得し、中心だけ対象ピン座標に置換する。元画面は移動させず、共有ダイアログを開いた時点の設定を固定する。URL更新のデバウンスによる古い設定のコピーを避ける。
- フィールドを列挙して名称・種別・経緯度・標高・DEM種別、選択されたメモだけを含める。UUID・作成日時・更新日時・他のピンは送らない。メモは既定オフ。URLは暗号化しない、内容はスナップショットで更新・失効機能はないことを共有画面に明記する。
- 受信時は圧縮展開後に型・座標範囲・文字数・ペイロードバージョン・重複パラメーターを検証する。名称100文字、メモ2000文字、DEM名称100文字、生成前の非圧縮URL上限24000文字。文字列はReactのテキストとして描画し、HTMLとして解釈しない。圧縮は暗号化ではなく、機密性や失効機能を与えない。
- 受信ピンは保存済み配列と分離して全Map共通のVectorSourceへ一時追加する。通常のエクスポート対象には含めない。移動・レイヤー変更のhash更新でも一時ピンを保持し、再読み込みできる。
- 明示保存時のみ新規UUIDで保存済み配列へ追加し、既存レコードを上書きしない。保存・破棄時は一時ピンとhashのペイロードを取り除き、再読み込みによる重複保存を防ぐ。同じURLを再度開いて保存する場合は別の複製となる。
- 通常の「表示URLをコピー」は受信URLからの丸ごとコピーをせず、地図設定だけで再構築する。コピー失敗時にも同一のURLを手動選択できる。ピン共有では公開サイトのorigin・サブパスを維持し、localhostではローカル専用と案内する。

## DEMと可変標高配色

中心緯度経度からWeb MercatorのXYZ・256px内座標を求め、DEM1A、5A、5B、5C、10Bの順でPNGを取得する。RGBを公式式で復号し、NA・HTTP・CORS・画像復号失敗は次候補または「取得不可」へフォールバックする。AbortControllerが古い移動の要求を破棄し、タイルPromiseキャッシュが同一取得を再利用する。

「解析用色別標高図」は、広域で欠測しにくく処理量を一定にしやすいDEM10Bを使う。取得した256pxタイルをCanvasで一度だけ復号・再配色し、通常のTileLayerとしてキャッシュする。地図の描画フレームごとに全画面を再計算するWebGL/raster演算は行わない。レンジ変更時は新しいSourceへ切り替え、保持するレンジ別Sourceキャッシュは最大8個、各Sourceのタイルキャッシュは128枚とする。

「表示範囲から推定」は、手動ボタンまたはペインごとの自動設定で、表示範囲の4×4＝16地点からDEM10Bを標本抽出する。自動設定でもmoveend後300msに一度だけ実行し、同じViewを共有する複数の自動ペインは一回の標本取得結果を共有する。同じレンジならReducerが更新を省略する。レンジと自動設定はhashへ保存する。等高線は端末でDEMから計算せず、試験公開MVTの既成線を既定オンで表示する。

## 操作時の更新量

中心座標・hash・標高はmoveend後だけ更新する。河川名ホバーは各ペイン内で `requestAnimationFrame` により高々1フレーム1回へ抑制し、ツールチップDOMだけを更新してReact全体を再描画しない。右クリック／長押しメニューとローカル検索は利用者操作時だけ動作する。

公式MVTは、ZL4～7の河川幅線、ZL8～13の通常部、ZL14以上の高詳細線へ地物コードと形状が切り替わる。単一Sourceを現在のズームだけで描くと、広域線を追って拡大した際に別形状へ置換され、見失いやすい。河川レイヤーは共有Sourceを2つ持ち、ZL7を上限とする一般化Sourceを高ズームでもオーバーズームし、大・中区分だけを破線の連続ガイドとして最前面に残す。通常のZL8～16 Sourceはズームに応じて線を太くし、`waterarea`も淡く重ねる。ZL8～10の詳細線とZL8以上の小区分ガイドを細く／非表示にして過密を抑える。MVTに管理区分がないため、一級河川・直轄・都道府県管理の推定分類は行わない。

一般化Sourceの追加要求は表示地点を含む低ズームタイルに限られ、すべてのMapでSourceを共有する。クライアント側の河川網解析や再計算は行わない。

初期state、hashの既定値、プリセットは共通のペイン生成関数を使い、主要道路・鉄道・河川中心線・等高線を既定オンにする。未表示のペインも同じ既定値で準備するため、1画面から2・4画面へ増やしたときにも参照レイヤーが有効になる。

## 責務分離

`config/` は公式レイヤーとプリセット、`domain/` は永続可能な型、`components/` はUI、`hooks/` はブラウザー・Reactライフサイクル、`services/` はOpenLayers生成・DEM・保存・ファイル変換・URL codecを担当する。外部データの可用性をCIの前提にしない。

## レイヤーパネルと外部観測施設

レイヤーパネルの開閉状態は`MapGrid`が一元管理し、すべてのペインで常に1つだけを開く。ペイン固有のレイヤー選択値は従来どおり独立して保持する。これにより、ペインごとの内容量にかかわらず開閉、Escape、フォーカス復帰の規則を揃える。

観測施設は、公開仕様のない内部APIや画面スクレイピングで取得しない。`riverObservationLinks`が現在中心とズームだけを国土交通省「川の防災情報」の公式マップURLへ設定し、利用者の明示操作で新しいタブを開く。ピン、現在地、GIS地物はURLへ含めない。
