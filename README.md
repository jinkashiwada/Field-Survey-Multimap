# 水害調査マルチマップ

水害時の痕跡調査、事前調査、現地踏査を行う研究者・学生・技術者向けに、国土地理院とハザードマップポータルの地理空間情報を複数画面で同期比較する静的Webアプリケーションです。Version 0.1はバックエンド、認証、APIキーを使用せず、GitHub Pagesだけで動作します。

公開版：<https://jinkashiwada.github.io/Field-Survey-Multimap/>

## 主な機能

- 1画面、同期2画面、PC・広いタブレットでの同期4画面
- ペインごとに独立した背景地図、重畳レイヤー、透明度、凡例・出典
- 低ズームでは衛星モザイクへ自動接続する「全国最新写真」背景地図
- 手動レンジまたは表示範囲の16地点標本から再配色する「解析用色別標高図」
- 試験公開ベクトルによる主要道路、鉄道、河川中心線・河川名、等高線
- 現在地と位置精度円、中心座標、国土地理院DEMによる概算標高
- localStorageへ保存する調査ピンの追加・編集・移動・削除
- ローカルKML・GeoJSONの読込み、ドラッグ＆ドロップ、KML・GeoJSON出力
- 右クリック／長押し地点へのピン追加、地理院地図・Googleマップ連携
- 座標、保存ピン名、読込みGIS地物名の端末内検索
- 現在の中心付近の水位計・危機管理型水位計・河川監視カメラを国土交通省公式マップで開く案内
- 表示状態をブラウザー内で圧縮したhash URLの共有、選択した1件のピンを含む任意共有

## 動作環境

iPhone・iPad・Android・Windows・macOS上の、現在サポートされているSafari、Chrome、Edge、Firefoxを対象にします。現在地にはHTTPSまたはlocalhostとブラウザー権限が必要です。4画面は1024×700 CSS px以上で利用できます。

## 開発を始める

Node.js 24（CIと同じメジャーバージョン）とnpmを用意します。Gitから取得した直後やCIでは、`package-lock.json`どおりに再現するため `npm install` ではなく次を使います。

```sh
npm ci
npm run dev
```

開発サーバーが表示するlocalhostのURLを開きます。変更前後の一括検証と本番ビルドは次のとおりです。

```sh
npm run check
npm run test:e2e
npm run build
```

`npm run check` はlint、型検査、単体テスト、buildを順番に実行します。E2Eを初めて実行する端末では、先に `npx playwright install chromium` を実行してください。本番成果物は `dist/` に生成されます。

### 開発時のCodex環境

Version 0.1の初期開発と本更新には、2026年9月3日時点のOpenAI Codex CLI 0.149.1を使用しました。確認時のローカル環境はNode.js 24.9.0、npm 11.6.0です。Codexは開発支援にのみ使用しており、公開アプリの実行時依存関係には含まれません。

## 使い方

ツールバーから画面数またはプリセットを選び、各画面の「レイヤー」で背景・重畳・透明度を設定します。初期表示、すべてのプリセット、画面追加時には主要道路・鉄道・河川中心線・等高線が有効です。2画面は端末の向きに合わせて上下または左右へ切り替わります。狭い画面で4画面URLや「痕跡調査総覧」を開くと、先頭2画面へ安全に縮退します。

「全国最新写真」は名称を統一したまま、ZL14以上で全国最新写真、ZL9～13で全国ランドサットモザイク、ZL2～8で世界衛星モザイクへ接続します。そのため広域から拡大しても写真系背景が途切れませんが、低ズームは航空写真ではなく衛星画像で、撮影時期・解像度も切り替わります。

低平地を詳しく見る場合は背景を「解析用色別標高図」にし、最小・最大標高を入力するか、地図左下の「表示範囲から配色レンジを推定」を使います。「移動後に自動推定」を有効にすると、pan・zoomの終了300ms後に表示範囲の16地点だけを標本抽出します。移動中の各フレームでは計算しません。自動設定はペインごとに選択でき、共有URLにも保存されます。再配色は新しい256px DEMタイルの受信時とレンジ変更時だけ行います。等高線は端末でDEMから生成せず、国土地理院の試験公開ベクトルを選択時だけ描画します。古い端末で発熱・電池消費が気になる場合は、自動推定をオフにして固定配色の「色別標高図」を使い、等高線もオフにしてください。

河川表示は、ZL6～7では公式タイルの一般化河川線を実線で示し、ZL8以上では大・中区分の一般化線を破線の連続ガイドとして残しながら、各ズームの詳細中心線と水域を重ねます。拡大時に主要河川を見失いにくくするための表示ですが、破線は低ズーム形状の拡大なので実河道とずれる場合があります。一級河川・直轄管理・県管理を表す区分ではありません。

地図上の河川名注記へマウスを重ねると河川名を表示します。地図を右クリック（タッチ端末は長押し）すると、その地点へのピン追加、中心移動、座標コピー、地理院地図・Googleマップで開く操作ができます。Googleマップを開く場合だけ、選択した座標がGoogleへ送られます。「検索」は緯度経度、保存ピン、読み込んだKML・GeoJSONの名称を端末内で検索します。全国の住所・河川名をオンライン検索する機能はVersion 0.1には含みません。

「観測施設」から、現在の地図中心付近を国土交通省「川の防災情報」で開けます。公式マップ上で水位計、危機管理型水位計、河川監視カメラの位置と、各施設の公式観測情報へのリンクを確認できます。このアプリ自身は施設位置やリアルタイム値を取得せず、リンクを開いた時だけ中心座標とズームを国土交通省サイトへ渡します。過去の水位を探すための水文水質データベースへのリンクも同じパネルにあります。

「現在地」は押した時だけ `getCurrentPosition` を呼び、常時追跡しません。位置は外部へ送らず、URLにも保存しません。中心標高は概況確認用であり、現地測量値ではありません。

「ピン追加」で地図中心にピンを作成します。ピンはこのブラウザーの `flood-multimap:pins:v1` に保存されます。ブラウザーデータを消すと失われます。

ピン一覧の「このピンを共有」を押すと、そのピンを中心にして現在の画面数・レイヤー・透明度・配色・ズーム・回転を再現するURLを作れます。名称・種別・座標・標高とDEM種別を含め、メモは「メモを含める」をオンにした場合だけ含めます。「ピン付きURLをコピー」で相手に渡してください。通常の「表示URLをコピー」は、共有ピンを受け取った後でもピン情報を含みません。どちらの共有URLもブラウザー標準機能でgzip圧縮し、`#s=1.` で始まるQRコード化しやすい形式にします。外部のURL短縮サービスやサーバーへ地図・ピン情報を送りません。

受け取った短いURLは起動時に端末内で展開され、アドレス欄が従来形式の長いhashに変わる場合があります。表示内容には影響しません。従来の`#v=1&...` URLも引き続き開けます。圧縮非対応ブラウザーでは従来形式へ自動フォールバックします。受け取ったピンは全画面に一時表示され、「自分のピンに保存」を押すと新しいIDでブラウザーに保存されます。「共有ピンを閉じる」では保存されません。URLを知る人は展開後の内容を読めるため、非公開情報を含めないでください。圧縮は暗号化ではありません。元のピンを後から変更・削除しても送付済みURLは変わらず、取り消しもできません。長文メモでは圧縮後もURLが長くなるため、画面の長さ表示を確認し、必要ならメモを外すかKML・GeoJSONを利用してください。他人へ渡すURLは公開サイト上で作成してください（localhostは自分の端末用です）。

「ファイル読込み」または表示パネルへのドロップで、EPSG:4326のKML・GeoJSONを読み込みます。最大20 MB・50,000地物で、KMZと外部URLは対象外です。「全地物へ移動」は読込み後に利用者が選択します。KML／GeoJSON出力は、保存ピンと読み込んだ地物をまとめてEPSG:4326で保存します。

## GitHub Pagesへ公開する

このリポジトリの公開URLは <https://jinkashiwada.github.io/Field-Survey-Multimap/> です。

1. GitHubへリポジトリを作成し、このブランチをpushしてmainへ反映します。
2. GitHubの **Settings → Pages → Source → GitHub Actions** を選択します。
3. mainへpushするか、Actionsの「Deploy GitHub Pages」を手動実行します。
4. 通常は `https://<username>.github.io/<repository-name>/`、`username.github.io` リポジトリは `https://<username>.github.io/` で公開されます。

Actionsでは `GITHUB_REPOSITORY` からViteのbaseを決めます。リポジトリ名を変更した場合は再デプロイしてください。独自ドメインではRepository Variable `PAGES_BASE_PATH` を `/` に設定します。明示設定する場合は先頭・末尾 `/` を含む `/<repository-name>/` 形式を推奨します。

## データ出典

- 背景・地形：国土地理院「[地理院タイル一覧](https://maps.gsi.go.jp/development/ichiran.html)」
- 道路・鉄道・河川・等高線：国土地理院「[地理院地図Vector（仮称）提供実験](https://maps.gsi.go.jp/development/vt_expt.html)」
- 浸水想定等：ハザードマップポータルサイト「[重ねるハザードマップのデータについて](https://disaportal.gsi.go.jp/hazardmapportal/hazardmap/copyright/opendata.html)」
- 概算標高：国土地理院「[標高タイルの詳細仕様](https://maps.gsi.go.jp/development/demtile.html)」
- 水位計・危機管理型水位計・河川監視カメラの案内：国土交通省「[川の防災情報](https://www.river.go.jp/kawabou/pc/tmlist)」「[水文水質データベース](https://www1.river.go.jp/contents.html)」

出典は地図内のOpenLayers Attributionと「設定・出典」でも確認できます。各データの利用条件は提供元の最新情報に従ってください。
